# Contributing to Koani

Thank you for your interest in contributing to Koani! We welcome contributions of all forms: bug fixes, new features, documentation updates, and sample improvements.

This document outlines our community guidelines, repository architecture, testing workflows, and submission processes.

## Community & Behavioral Expectations

We are committed to providing a welcoming, respectful, and harassment-free environment for everyone, regardless of background, experience level, or identity.

- Be respectful, constructive, and empathetic in all interactions (issue comments, code reviews, PR discussions).
- Focus on what is best for the community and project.
- Gracefully accept constructive criticism.

## Policy on AI Assistance

Using AI tools (such as GitHub Copilot, ChatGPT, Claude, or Gemini) is permitted and welcomed to help write code, generate tests, or draft documentation, provided you follow these rules:

- **Understand & Review:** You must thoroughly review, understand, and test any code generated by AI before submitting a Pull Request.
- **Accuracy & Quality:** AI-generated code must adhere to the project's coding standards, Detekt rules, and architecture.
- **No Untested Submissions:** Do not open PRs with unverified or blindly pasted AI output.

## How to Contribute

### Reporting Issues

Before opening a new issue, search existing issues to see if it has already been reported.

#### Bug Reports
- Use the Bug Report issue template.
- Provide a minimal reproducible code snippet.
- Include environment details (Koani version, Kotlin version, Target platform, OS).
- List exact steps to reproduce the issue.

#### Feature Requests
- Use the Feature Request issue template.
- Explain the problem your feature solves and the proposed API design.
- Specify which target platforms (e.g. Common KMP, Android, iOS, JVM, JS, WasmJS) are affected.

### Submitting Pull Requests

1. Fork the repository and create a feature branch off [main](file://symbol://main) (e.g., `feature/anime-ranking-paging` or `fix/oauth-token-refresh`).
2. Implement your changes, following code style and architecture conventions.
3. Add or update unit tests to cover your changes.
4. Run static analysis (`./gradlew detekt`) and tests (`./gradlew check`) locally.
5. Open a Pull Request targeting [main](file://symbol://main) and complete all sections of the PR template.

## Repository Architecture & Codebase Organization

Koani is structured as a Kotlin Multiplatform (KMP) project:

```
koani/
├── koani-core/                      # Core KMP library targeting Android, iOS, JVM, JS, WasmJS
├── koani-auth-persistence-ksafe/    # Secure token persistence integration using KSafe
├── integration-tests/               # Live integration test suite against MyAnimeList API
├── samples/                         # Example applications
├── docs-site/                       # Docusaurus documentation website
```

### Core Architecture Concepts
- **KoaniClient:** Main entry point constructed via builder or DSL.
- **Dependency Injection Container `KoaniContainer`:** Internal lightweight container that holds configuration (HTTP engine, timeouts, logging severity, token managers) and wires up internal Ktor services.
- **Service Modules:** Organized by domain (`client.anime`, `client.manga`, `client.user`, `client.forum`, `client.auth`).
- **Data Models:** Immutable Kotlin data classes annotated with `kotlinx.serialization.Serializable`.
- **Error Handling:** API errors are surfaced via `KoaniException` hierarchy.

## Development Workflow & Testing

- JDK 17
- Node.js 22+ (for `docs-site` development)

```./gradlew koverHtmlReport```

```./gradlew :samples:assemble -PincludeSamples=true```

## Integration Testing Guide

Integration tests live in `:integration-tests` and test against the real MyAnimeList API. They are separated from unit tests to avoid rate limiting and unexpected external network calls during normal builds.

### Running Integration Tests
Integration tests do not run during `./gradlew check`. Run them explicitly with:

```./gradlew :integration-tests:integrationTest```

#### Credentials Configuration
Tests require API credentials depending on whether they are unauthenticated or authenticated:

- **Unauthenticated tests:** Require `TEST_MAL_CLIENT_ID`.
- **Authenticated tests:** Require `TEST_MAL_CLIENT_ID`, `TEST_MAL_ACCESS_TOKEN`, and `TEST_MAL_REFRESH_TOKEN`.

Provide credentials using any of the following methods (in order of resolution precedence):

1. **Gradle Properties / Command Line Flags:**
   ```bash
   ./gradlew :integration-tests:integrationTest \
     -PTEST_MAL_CLIENT_ID="your_client_id" \
     -PTEST_MAL_ACCESS_TOKEN="your_access_token" \
     -PTEST_MAL_REFRESH_TOKEN="your_refresh_token"
   ```

2. **Environment Variables:**
   ```bash
   export TEST_MAL_CLIENT_ID="your_client_id"
   export TEST_MAL_ACCESS_TOKEN="your_access_token"
   export TEST_MAL_REFRESH_TOKEN="your_refresh_token"
   ./gradlew :integration-tests:integrationTest
   ```

3. **`local.properties` File (in project root):**
   ```properties
   TEST_MAL_CLIENT_ID=your_client_id
   TEST_MAL_ACCESS_TOKEN=your_access_token
   TEST_MAL_REFRESH_TOKEN=your_refresh_token
   ```

> **Warning:** Never commit credentials or `local.properties` to version control.

### Writing New Integration Tests

1. Inherit from `BaseIntegrationTest`.
2. Use `runIntegrationTest { client -> ... }` for unauthenticated tests or `runIntegrationTest(authenticated = true) { client -> ... }` for authenticated tests.
3. Wrap **every** API request in `performRequest { ... }`. This uses a global `Mutex` to enforce a mandatory 1-second cooldown between requests across the suite.

```kotlin
class MyFeatureIntegrationTest : BaseIntegrationTest() {

    @Test
    fun `fetch anime details successfully`() = runIntegrationTest { client ->
        val details = performRequest {
            client.anime.getAnimeDetails(animeId = 5114)
        }
        assertEquals("Fullmetal Alchemist: Brotherhood", details.title)
    }
}
```

### Rotating Test Tokens
Authenticated tests require valid OAuth credentials. Use the built-in token rotation task to refresh credentials:

```./gradlew :integration-tests:rotateTestTokens```

Follow the printed localhost URL instructions in your browser to complete PKCE authorization and update your test tokens. Never commit test tokens or credentials to version control.

## Updating Samples & Documentation

### Updating Sample Applications

When introducing new API methods or breaking changes:
- Update `samples/cli` to demonstrate command-line usage.
- Update `samples/compose` to ensure sample UI apps build cleanly.
- Verify samples compile with `./gradlew :samples:assemble -PincludeSamples=true`.

### Updating the Documentation Site

Documentation is built with Docusaurus v3 in `docs-site/`:

1. Navigate to docs directory:
   ```cd docs-site```
2. Install dependencies:
   ```npm ci```
3. Start local development server:
   ```npm run start```
4. Verify build before submitting PR:
   ```npm run build```

### Generating Dokka API Reference

To generate public Dokka HTML documentation:

```./gradlew dokkaGenerateHtml```

Output docs will be generated in `build/dokka/html`.
